## 启动器逻辑问题（已修复）

1. **整合包完整更新残留旧模组**：增量更新会删除旧版本管理的文件，但完整安装路径不会。overrides 变化会强制走完整安装，旧 jar 会和新 jar 并存，可能导致重复模组崩溃。现在完整安装会按增量规则删除旧版本管理、新索引不再包含的文件，用户自行添加的文件不受影响（新增 `FullInstallCleanupTests`）。
2. **启动前自动更新使用过期清单**：此前优先使用打开启动器时缓存的清单，启动器长时间运行期间发布的新 revision 不会在启动前更新。现在先获取最新签名清单，失败时再回退到缓存。
3. **游戏退出状态不区分崩溃**：正常退出、用户结束和崩溃都显示“游戏已退出”。现在非零退出码显示“游戏异常退出（代码 N）”，并根据已有输出分类给出中文提示（内存不足、Java 过低、模组不兼容、显卡驱动等）。
4. **Quilt 安装无超时和错误映射**：与 Fabric 一致，使用 45 秒超时，网络错误转为可读提示。
5. `GameLauncherVersion` 固定为 `0.1.0`：改为当前启动器版本。

## 启动时的皮肤站连接（2026-11-07）

原先有保存的登录时，启动器在显示任何窗口前同步向皮肤站验证（最长 20 秒超时），期间没有任何画面；网络错误也会清除登录、退回登录窗口。

现在的行为：

| 情况 | 处理 |
| --- | --- |
| 没有保存的登录 | 直接显示登录窗口（不联网） |
| 有保存的登录 | 立即打开主界面，后台验证；账户名上方显示“正在确认…” |
| 验证或刷新成功 | 静默更新会话，显示“已登录” |
| 皮肤站明确返回登录失效 | 清除保存的登录，弹出主题提示“登录已失效”，可立即重新登录或稍后在启动游戏时再登录 |
| 网络错误、超时或皮肤站 5xx | 保留登录、不弹登录，启动游戏前会再次验证；账户下方显示一行提示（悬停查看原因），文字按下面的诊断结果区分 |

### 区分皮肤站故障和用户网络问题

单次请求失败无法判断是哪一方的问题，因此 `Network/ConnectionDiagnosis.cs` 会先诊断：

1. 皮肤站返回的普通错误（如密码错误、令牌被拒）不算连接问题。
2. 本机没有已连接的网卡：用户网络问题，不再探测。
3. 通过相同的代理设置同时访问 msftconnecttest、百度和启动器服务器，任一返回 HTTP 响应即说明互联网正常；全部失败则判定为用户网络（或代理）问题。
4. 互联网正常时再请求一次皮肤站 API 根地址：仍然连不上或返回 5xx，才判定为皮肤站故障；这次又能连上则视为网络波动。

| 诊断结果 | 提示文字 | 群聊截图 |
| --- | --- | --- |
| 皮肤站故障 | 皮肤站现在已经坚不可摧（悬停说明：无法连接皮肤站，请检查皮肤站状态） | 悬停提示和启动失败提示中显示 |
| 用户网络问题 | 网络连接不可用（请检查网络连接或代理设置） | 不显示 |
| 无法确定 | 暂时无法连接皮肤站 | 不显示 |

启动游戏前本就会通过 `AuthSessionGate` 验证并在需要时重新登录，因此启动时不再阻塞验证不影响安全性。测试见 `tests/LauncherSettings.Tests/AuthRecoveryChecks.cs` 的 `StartupVerificationChecks`。
